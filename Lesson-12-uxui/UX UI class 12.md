# 🎯 **Планирование проекта**

⏱ _Время: 30 минут_

---

## 🧩 **Детальный пользовательский сценарий**

---

### 🔹 **1. Открытие приложения (Entry Point)**

- 👤 Пользователь открывает **веб** или **мобильное** приложение
    
- 🖼 Появляется _Splash Screen_ или сразу **форма логина**
    
- ✅ Если есть **сохраненная сессия** → мгновенный переход на **Dashboard**
    

---

### 🔹 **2. Взаимодействие с формой логина**

#### 🔄 **Основной поток:**

- Пользователь видит поля **Email/Логин** и **Пароль**
    
- 🔲 Кликает по полю → появляется **анимация фокуса**
    
- ⌨️ Вводит email → **валидация в реальном времени**
    
- 🔒 Вводит пароль → возможность **показать/скрыть символы**
    
- 🔘 Нажимает **"Войти"** → кнопка переходит в **состояние загрузки**
    

#### ⚠️ **Альтернативные сценарии:**

- ❓ _Забыл пароль_ → переход на восстановление
    
- ➕ _Нет аккаунта_ → переход на регистрацию
    
- 🚫 _Неверные данные_ → ошибка с **анимацией**
    
- 📡 _Проблемы с сетью_ → показ соответствующего уведомления
    

---

### 🔹 **3. Процесс входа и переход**

- ⏳ После нажатия **"Войти"**: отображается **спиннер**
    
- 🧠 Валидация на сервере (имитация: `2–3 сек`)
    
- ✅ Успех → **анимированный переход** на дашборд
    
- ❌ Неуспех → возврат + **сообщение об ошибке**
    

---

### 🔹 **4. Первое появление дашборда**

- 🎞 Элементы появляются **по очереди (staggered animation)**
    
- 👋 Приветствие с **именем/аватаром пользователя**
    
- 📦 Основной контент загружается постепенно
    
- 🧭 Навигация активируется после загрузки
    

---

### 🔹 **5. Выход из аккаунта**

- 🚪 Клик по **"Выйти"** в меню или хедере
    
- ✅ Опциональное **подтверждение действия**
    
- 🔄 Плавный **переход назад** к форме логина
    
- 🧹 Очистка **данных сессии**
    

---

## 🧠 **Определение ключевых состояний (States)**

---

### 🗂 **Форма логина:**

| Состояние | Описание          |
| --------- | ----------------- |
| `Empty`   | Пустые поля       |
| `Focused` | Активное поле     |
| `Filled`  | Поля заполнены    |
| `Valid`   | Корректные данные |
| `Invalid` | Ошибки валидации  |
| `Loading` | Процесс входа     |
| `Success` | Успешный вход     |
| `Error`   | Ошибка входа      |

---

### 🗂 **Дашборд:**

| Состояние     | Описание            |
| ------------- | ------------------- |
| `Loading`     | Загрузка данных     |
| `Loaded`      | Успешная загрузка   |
| `Empty state` | Нет данных          |
| `Error state` | Ошибка при загрузке |

---

## 🔄 **Определение переходов (Transitions)**

---

### ⚙️ **Микроанимации:**

- 🎯 Фокус на поле ввода: `200ms ease-out`
    
- 🖱 Hover на кнопке: `150ms`
    
- 🚨 Ошибки: `300ms bounce`
    
- 🔄 Загрузка: **пульсация**
    

---

### 🎬 **Макропереходы:**

|Переход|Анимация|
|---|---|
|`Логин → Дашборд`|`500–800ms slide/fade`|
|`Дашборд → Логин`|`400ms fade-out`|
|`Элементы дашборда`|`staggered`, `100ms delay`|

---

### **Схема переходов (Flow Diagram):**

```
Вход в приложение
       ↓
   Форма логина ←──────────┐
       ↓                  │
   Валидация              │
       ↓                  │
   ┌─ Ошибка? ────────────┘
   │       ↓ Нет
   │   Загрузка
   │       ↓
   │   ┌─ Ошибка сервера? ──┐
   │   │       ↓ Нет        │
   │   │   Успешный вход    │
   │   │       ↓            │
   │   │   Переход          │
   │   │       ↓            │
   │   │   Дашборд ←────────┘
   │   │       ↓
   │   │   Выход ───────────┐
   │   │                    │
   │   └─ Логин ←───────────┘
   │
   └─── Повтор ввода
```

### **Практические рекомендации для Figma:**

1. **Создайте отдельные фреймы** для каждого состояния
2. **Используйте Auto Layout** для адаптивности
3. **Создайте компоненты** для переиспользуемых элементов
4. **Добавьте варианты состояний** (states) в компоненты
5. **Настройте Smart Animate** между ключевыми переходами
6. **Добавьте overlay** для модальных окон ошибок
